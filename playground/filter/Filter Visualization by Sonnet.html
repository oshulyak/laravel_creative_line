Как работает фильтр Post

Путь запроса GET /api/posts?... от HTTP до JSON-ответа: роутинг, валидация, механизм Eloquent Local Scope (filter() → scopeFilter()) и классы PostFilter / AbstractFilter. Кликай по узлам схемы — там код и место для заметки.

Что скорректировано в твоём описании
  1. Запрос — GET, не JSON. Фильтры приходят через query string (?author_id=1&title=...), а не в JSON-теле. JSON — это формат ответа, не запроса.
  2. Добавлены роутинг и валидация. Перед телом index() запрос проходит routes/api.php, а IndexRequest валидирует query-параметры ещё до выполнения кода контроллера.
  3. Уточнён механизм п. 4–6. Builder не «ищет метод через trait» напрямую: сначала он не находит filter() среди своих методов, затем по механизму Local Scopes обращается к модели Post (на которую у него есть ссылка) и находит там scopeFilter() — этот метод в Post появляется именно благодаря трейту HasFilter.
  4. Добавлен ->with('category'). В реальном коде контроллера категория подгружается заранее (eager loading) между filter() и get() — иначе будет N+1 запрос.
  5. Добавлен шаг PostResource::collection(). resolve() вызывается не «сам по себе», а на обёртке коллекции ресурсов, которая создаётся отдельным шагом после get().
