GET /api/posts?…──▶JSON-ответ

Интерактивная схема: как HTTP-запрос проходит через фильтр постов. Кликайте узлы или листайте шаги «Далее», чтобы проследить путь от контроллера через trait HasFilter, scopeFilter(), PostFilter и AbstractFilter::apply() до итогового ресурса. Оранжевой меткой «исправлено» отмечены места, уточнённые относительно исходного представления.

HTTP-слой
1HTTP-запросGET
GET /api/posts?title=laravel&category_id=3 — query-параметры, не JSON-body
▼
2IndexRequest · валидацияFormRequest
rules() проверяет параметры → в контроллер уходит только $request->validated()
▼
3PostController@index
Post::query()->filter($data)->with('category')->get()
▼
Модель · Eloquent Builder
4Post::query() → Builder
Создаётся Eloquent\Builder; внутри он хранит ссылку на модель Post ($builder->getModel())
▼
5->filter($data)магия scope
Метода filter() на Builder нет → Builder::__call ловит вызов и ищет локальный scope модели
6 · HasFilter::scopeFilter($builder,$data)
Соглашение: filter → scopeFilter. Trait подключён к Post, поэтому scope виден Builder’у. Формирует имя класса: App\Filters\PostFilter из class_basename($this).'Filter' и вызывает (new PostFilter)->apply(...).
▼
7new PostFilter → apply()
PostFilter хранит белый список $keys разрешённых для фильтрации атрибутов
8-9 · AbstractFilter::apply($builder,$data)
foreach по $keys → если isset($data[$key]), вызывается одноимённый метод Str::camel($key) уже в PostFilter. Сам apply условий не пишет — он диспетчер.
▼
10Методы-условия PostFilter
id()/title()/categoryTitle()… добавляют where / whereRelation в тот же $builder
▼
Результат · ответ
11->get() → Collection<Post>
Builder с накопленными where выполняет SQL; category подгружена заранее (eager load)
▼
12PostResource → resolve() → JSON
PostResource::collection($posts)->resolve() → массив → HTTP-ответ JSON
